# Agave Threat Model

Living model of what this codebase exposes to attack, what it costs when attacked, and which controls stand in the way. Findings feed sec-review; this file does not prescribe code fixes.

- **Last reviewed:** 2026-10-07 (every `path:line` below re-resolved by symbol against source in this pass)
- **Owner / review cadence:** organizational fields, to be assigned; not defined in-repo
- **Scope:** inference CLI (`src/main.zig`), HTTP server (`src/server/`), model loaders (`src/format/`), Hub downloads (`src/pull.zig`), the self-updater (`src/update.zig`), distributed transports (`src/parallel/`), WASM/browser demo (`web/`, `src/wasm_entry.zig`), container artifacts (`Dockerfile`, `docker-compose.yml`)
- **Out of scope:** backend kernel internals beyond their input parsing; GPU driver attack surface

Disclosure and supported-version policy: [SECURITY.md](../SECURITY.md). HTTP contract: [API.md](API.md).

Every reference below is `path:line` plus the symbol or literal at that line, so a later drift is cheap to detect without a full re-read. Line numbers here were resolved by symbol, not copied from the previous revision: `rg -n 'fn <symbol>' <file>` first, then confirm the literal on the returned line. A reference that no longer resolves at the named symbol is stale, not approximate. `zig build docs-check` (`scripts/check-docs.py` `check_doc_line_refs`) catches only the gross form of drift — a missing file or a line past EOF — so symbol-level re-resolution still has to be done by hand.

## Risk-ranked summary

| # | Threat | Boundary | Impact | Status |
|---|--------|----------|--------|--------|
| T1 | Any LAN host can join an inference cluster or inject tensors: TP/PP/disagg/discovery have no authentication | Peer node -> node (TCP 49454/49455/49456; UDP discovery reuses the same numbers) | Wrong outputs accepted as correct; full prompt transcript theft via disagg KV stream | **No mitigation.** No peer credential check anywhere in `src/parallel/` |
| T2 | `agave update` overwrites the running executable with bytes from a third-party host; the SHA-256 sidecar it checks against is fetched from the same host in the same run | GitHub -> local filesystem | Arbitrary code execution as the invoking user, at the next start of the binary | Partial: HTTPS-only, `trustedGithubUrl` host allowlist, SHA-256 sidecar, size caps. No signature, no pinned digest: T9 |
| T3 | Downloaded models are not content-integrity-checked: `resolve/main`, magic/size only | HF Hub -> loader | Poisoned weights steer outputs; malicious GGUF/SafeTensors exercises parser bugs | Partial: TLS + parser caps + GGUF magic |
| T4 | Single-key deployments have no tenant separation: `/v1/kv_cache` export and the global prompt-prefix / radix cache cross request owners | Client -> client (same server) | One API-key holder reads KV state derived from another user's prompts | Documented limitation, unmitigated |
| T5 | Rate limiting is one global bucket, default off; grammar/json_mode bypass the batch scheduler | Client -> compute | One client exhausts GPU time / latency for all | Partial: caps exist, identity does not |
| T6 | Predictable shared-memory names let any same-uid local process read/inject tensors | Local process -> shm | Local tensor injection during `--tp 2` same-host runs | Mode 0600 + `O_EXCL` after `shm_unlink` only |
| T7 | Conversation store persists prompts to disk (`$XDG_CACHE_HOME/agave/conversations.json`); `action=delete` destroys the live copy | Process -> filesystem | Prompt transcript survives process exit and, for a deleted conversation, survives until the pre-deletion sidecar or the backup tier is also lost | Owner-only mode 0600 (`durable_file.private_file_mode`), pre-deletion snapshot `conv_store.snapshotBeforeDelete`, no encryption; compose volume `agave-cache` holds it |
| T8 | `/v1/tokenize` and `/v1/detokenize` run the tokenizer on attacker-chosen text with no per-endpoint quota | Client -> compute | Tokenizer CPU burn on loopback deployments; detokenize is a decode oracle over vocabulary | Bounded by 1 MiB body and 128-message scan cap; no endpoint-level rate limit |
| T9 | The idempotency replay ledger is global and keyed only on the client-supplied `X-Request-Id` | Client -> client (same server) | One key holder replays another holder's stored `/v1/chat` reply (up to 64 KiB, 1 h retention), or suppresses their retry | Unmitigated; the key carries no principal |
| T10 | `POST /v1/kv_cache` lets any key holder write attacker-chosen f32 hidden state into the live cache; `n_tokens` alone sizes the write | Client -> compute (and client -> client) | Every later answer for that slot is computed over injected K/V. Bounded by `importKvPrefix` size checks (`src/models/gemma4.zig:1654`), not by any integrity control | Partial: length-validated against per-layer KV, taken under the model + scheduler locks (`src/server/server.zig:3040-3046`) |
| T11 | `--kv-tiers vram+ram+ssd` spills live KV hidden state to a world-readable `0644` file at the operator-supplied `--kv-ssd-path` | Process -> filesystem | Any local user reads prompt-derived KV from the SSD tier; the file is deleted on clean shutdown (`src/kvcache/tiered.zig:344`), so a crash leaves it behind | Path traversal / absolute-path / NUL rejected (`src/kvcache/tiered.zig:238-241`); **file mode is `0644`, not the private mode the conversation store uses** |
| T12 | A `.cal` file sitting next to the model is auto-loaded under `--kv-eviction tri` and silently steers eviction scoring; the path is derived, never operator-supplied | Artifact -> process (implicit) | Co-located file changes which KV positions survive, degrading or skewing answers with no command-line trace | Partial: magic + version + length checks (`src/calibrate.zig:550-585`), non-finite `theta` rejected (`src/ops/kv_evict.zig:358`); no signature and no prompt to confirm the file was expected |

Highest-value correction for operators: **the API key protects only TCP 49453**. The TP/PP/disagg data ports and UDP discovery are separate listeners that never see it. Within 49453 the key authenticates but does not partition: everything a key holder sends shares one KV cache, one radix prefix cache, one conversation store, and one replay ledger.

## Assets

- The installed `agave` binary: `agave update` replaces it in place (`replaceVerified` `src/update.zig:193`, caller `replaceExecutable` `src/update.zig:364`), so compromising the download path is code execution with the operator's privileges. T2.
- Model weights on disk and in VRAM: expensive to obtain, exfiltration target.
- Prompt and conversation content: in memory; in the bounded conversation store (`max_conversations` = 100 `src/server/conv_store.zig:43`, `max_messages_per_conv` = 1000 `:44`, re-exported into the server at `src/server/server.zig:118,119`); on disk via `src/server/conv_store.zig` (`defaultPath` `:107`, `$XDG_CACHE_HOME` `:108` else `$HOME` `:109`); latent in the KV cache and radix prefix cache (`src/server/scheduler.zig` `radix_tree` field `:314`, `matchPrefix` call `:434`, `insert` call `:719`).
- Generated response bodies retained for replay (`src/server/idempotency.zig` `max_body_len` 64 KiB `:56`, `retention_ms` 1 h `:61`, `in_flight_ttl_ms` 5 min `:58`).
- Hidden states: `/v1/kv_cache` export returns raw per-layer KV blocks, capped at 64 MiB (`kv_export_max_bytes` `src/server/server.zig:113`, route `src/server/server.zig:2957`). The same values can be **written in** by import (`src/server/server.zig:3047`) and are spilled to disk when the SSD tier is on (`src/kvcache/tiered.zig:549`): T10, T11.
- Credentials in process env: `HF_TOKEN` (`src/pull.zig:338` `config.getenv("HF_TOKEN")`), `GITHUB_TOKEN` (`src/update.zig:455`), `AGAVE_API_KEY` (`src/main.zig:1381` `preferredSecret`, definition `:1674`).
- GPU compute and availability: generation is the costly resource; DoS converts directly to cost.
- Output integrity: poisoned weights, a poisoned allReduce, or an update-channel substitution silently corrupt every answer.

## 2. Trust boundaries and data flow

1. **Client -> HTTP API.** Authn point: one dispatcher chokepoint, `authorizedForPath` (`src/server/server.zig:1414`, call site `:2337`, table lookup `authPolicyFor` `:430`), which calls `validateAuth` (`:1387`, constant-time compare helper `constantTimeEql` `:1425`) for every route whose `known_endpoints` entry is `AuthPolicy.required`. The default for a new or unlisted path is `required` (`src/server/server.zig:404,430`), so a route cannot become reachable without the key by omitting a check; only `/health` and `/ready` (`.optional`) and `/favicon.ico` (`.public`) opt out, and the first two still trim their body when `validateAuth` fails (`:2363`, `:2384`). Deny side pinned by `test "auth chokepoint denies every protected route"` (`:9528`, unknown-path and case-variant asserts `:9562-9563`). Policy: non-loopback binds refuse to start without a key (`src/main.zig:1386`), and an empty key is rejected rather than accepted as "present" (`src/main.zig:1394`); loopback binds are open by design. Unauthenticated mode additionally rejects non-loopback `Host` (DNS rebind, `isRebindHostUnauthenticated` `src/server/server.zig:1110`, applied `:2287`, backed by `isLoopbackHttpHost` `src/server/http.zig:178`), mismatched `Origin` vs `Host`, and `Sec-Fetch-Site: cross-site` (CSRF / drive-by browser, `isCrossOriginUnauthenticated` `src/server/server.zig:1124`, applied `:2300`, over `isCrossSiteFetch` `src/server/http.zig:149` and `originMatchesHost` `src/server/http.zig:128`). A client that sends none of those headers (curl, SDKs, probes) is unaffected.
2. **Client -> client (same server).** No principal is derived from the key. The KV cache, radix prefix cache, conversation store, and idempotency ledger are all per-server singletons shared by every request: T4, T9.
3. **Artifact -> loader.** Whoever supplies the file (local user, Hub download, LoRA adapter, mmproj, PNG/PPM) crosses into mmap/decode native code. Validation lives inside the parsers (see mitigations).
4. **HF Hub -> local cache.** Transport-authenticated (TLS) but content-unverified; blobs land under `$HF_HOME`-derived paths with `O_NOFOLLOW` writes (`src/pull.zig:1335`). Commit SHA is used for snapshot directory naming, not as a pin on the download URL (`resolve/main` `src/pull.zig:1140`).
5. **GitHub releases -> local filesystem.** `agave update` is the only code path that overwrites a file the user executes. The channel is HTTPS with a GitHub host allowlist (`trustedGithubUrl` `src/update.zig:127`, userinfo and `github.com.evil.com` refused, tests `:584-586`), and the payload must match a `.sha256` sidecar (`checksumMatches` `:159`, sidecar name `writeSidecarName` `:83`). Both the asset and the sidecar come from the same release in the same run, so the digest proves transfer integrity, not publisher identity: T2. No code signature, no pinned digest, and the sidecar is not itself signed.
6. **Peer node -> this node (TP/PP/disagg).** No authentication point exists anywhere on this boundary. Any host that connects is accepted into a rank slot subject only to the `max_peers` cap (`src/parallel/transport.zig` `acceptPeer` `:312`, connect-side check `:270`); first UDP `AGAVE-JOIN` responder wins discovery (`src/parallel/peer_discovery.zig:65`). Largest unauthenticated boundary.
7. **Same-host processes -> shm segments.** Only uid/file-mode checks; names are fixed.
8. **Secrets -> process.** Env vars enter once at startup; nonempty `AGAVE_API_KEY` wins over CLI to avoid `ps` exposure (`src/main.zig:1222-1226`, `preferredSecret` `:1674`); empty env is unset. `GITHUB_TOKEN` is read by `agave update` and is sent as a bearer to `api.github.com` only (`src/update.zig:455`). Rotation: process restart. Storage: env only. Prompt-derived buffers are wiped before free (`wipeFree` / `wipeFreeTokens` `src/server/server.zig:1162,1168`), the per-connection read buffer that carries `Authorization` / `x-api-key` is zeroed before it is freed (`:7557`, freed `:7559`), and Hub `Authorization` buffers are zeroed (`src/pull.zig:809,1234`).
9. **Process -> conversation file.** Prompts written to the cache-path conversation store unless `--no-conv-store` (`src/server/conv_store.zig` `defaultPath` `:107`, `save` `:130` via `durable.replacePrivate` `:140`). Compose maps this under `agave-cache` (`docker-compose.yml:65`). A destructive API call (`action=delete` `src/server/server.zig:3474`, plus the UI `/clear` and `/reset` commands) snapshots the store aside first (`snapshotBeforeDeletion` `src/server/server.zig:3961` -> `conv_store.snapshotBeforeDelete` `src/server/conv_store.zig:275`, `{path}.deleted[.N]` at owner-only mode, `max_sidecar_copies` 8 `:552`); the snapshot is best-effort and its failure is logged, not fatal, so a full sidecar tier degrades to the backup tier alone.
10. **Embedded UI -> jsDelivr.** `src/web/chat/markdown.ts` fetches marked / DOMPurify / highlight.js from `cdn.jsdelivr.net` (URLs `:13,15,17`, pinned SRI hashes `:14,16,18`) with the hashes checked in `loadCdnScript` (`:54`, `script.integrity` `:57`) on the first response and the first code block rather than on page load. A stalled CDN resolves false after the timeout so the plain-text fallback settles. CSP allowlists that origin for scripts only (`src/server/http.zig:384`); no stylesheet is fetched, so `style-src` stays `'unsafe-inline'` alone. Compromise of the CDN without a matching hash is blocked; a rebuild that changes both script and hash is a build-time event.

Privilege transitions: none at runtime. The process starts and stays at its launching privilege; the Dockerfile drops to `agave` before exec (`Dockerfile:246`), and compose adds `no-new-privileges` (`docker-compose.yml:75`). `agave update` is the one deliberate write to an executable the user runs (`src/update.zig:364`), gated on the verdict of `decide` (`:177`) and confined to the release asset's bytes.

## 3. Threats per boundary

**Client -> HTTP API**
- Spoofing: key guessing. Mitigated: constant-time compare, non-empty key enforcement (`src/server/server.zig:1387,1425`, `src/main.zig:1386,1394`).
- Information disclosure: `/health` and `/ready` reachable unauthenticated (reduced bodies; `docs/API.md` health/ready sections match code at `src/server/server.zig:2353-2420`). Residual: build info on `/metrics` requires auth (`:2424`); `/v1/models` (`:2465`) discloses model geometry to any key holder.

CLI default is 0 = limiter disabled (`src/main.zig:681,683`, wired `:3969`; unset side falls back to `rate_limit_unlimited_rpm` / `_tpm` `src/server/server.zig:133-134`, install site `:7728-7731`). - Repudiation: request identity is a client-supplied `X-Request-Id`, length-capped (`max_client_request_id_len` `:100`, sanitize `sanitizeClientRequestId` `src/server/http.zig:117`, capture `captureClientRequestId` `src/server/server.zig:1101`), so a log line cannot be tied to a client beyond a self-declared id.

**Client -> client (shared server state)**
- Information disclosure: `/v1/kv_cache` export (`:2957`) returns blocks derived from other holders' prompts; the radix prefix cache matches across requests (`src/server/scheduler.zig:434`, insert `:719`).
- Information disclosure via replay: the ledger stores the response body for 1 h under the caller's `X-Request-Id` (`src/server/idempotency.zig:56,61`, claim `:161`) and answers a matching key with those bytes (`src/server/server.zig:1505`, dispatch `:1474`). A second key holder who learns or guesses that id receives the first holder's completion without supplying the prompt: T9. The ring is 64 keys (`capacity` `:52`), so guessing is not even necessary for a client that can observe its own ids in the same deployment.
- Tampering/DoS: presenting a key that is `in_flight` yields a duplicate rejection (`src/server/server.zig:1475`), so a hostile holder can deny another holder's retry (in-flight TTL 5 min `src/server/idempotency.zig:58`).
- Tampering of model state: `POST /v1/kv_cache` (`:2957`) reads `n_tokens` from the query (`:2961`, `parsePositiveQueryParam`) and hands the body to `importKvPrefix` (`:3047`) under the server mutex plus the model and scheduler locks (`:3040-3046`). Nothing else validates it: the f32 values are attacker-chosen, `kv_seq_len` becomes `n_tokens` (`:1669`), the device KV mirror is invalidated (`:1673`), `kv_valid = true` (`src/server/server.zig:3049`), and every later answer on that slot is computed over the injected hidden state. T10.
- Repudiation of destruction: `action=delete` (`:3474`) has no ledger claim, so a retried or replayed delete is not deduplicated. The pre-deletion snapshot (`src/server/conv_store.zig:275`) is the only in-process record of what the conversation contained.

**Artifact -> loader (GGUF/SafeTensors/LoRA/PNG/PPM)**
- Tampering/DoS: crafted headers driving huge allocations or OOB. Mitigated: GGUF metadata/tensor/array/alignment caps (`src/format/gguf.zig:20-28`), saturating size math (`tensorBytes` `:162`), tensor offsets validated against file size in `parseHeader` `:860`; SafeTensors header capped at 100 MB and checked against file size (`src/format/safetensors.zig:20,264`); shard-name traversal blocked (`isSafeShardName` `:2217`); PNG dimension/inflate caps (`src/image.zig:21,24,27`, enforced `:133,176`).
- Tampering on a failing LoRA apply: an adapter that fails partway used to leave published overrides in the map. Mitigated now: the apply publishes then records, and an append failure restores the previous override or removes the fresh entry (`src/lora.zig:86`, rollback `:209`), pinned by `test "a failed apply rolls every override back"`.
- Residual: unknown GGUF type codes fall back conservatively (`src/format/gguf.zig` default branch on the type switch; non-string arrays are skipped). Fuzz coverage exists: GGUF (`src/format/gguf.zig:1761,1867`), SafeTensors (`src/format/safetensors.zig:4328`), PNG/PPM (`src/image.zig:729`).

**HF Hub -> loader (supply chain)**
- Tampering: repo contents change between listing and blob GET; branch `main` is fetched, not the listed SHA (`src/pull.zig:1140`). Verification ends at GGUF magic bytes + Content-Length match (`verifyGgufBlob` `src/pull.zig:1570`): T3.
- DoS: a hostile or compromised endpoint that accepts the connection and then stalls is bounded by `api_stall_timeout_sec` (60 s, `src/pull.zig:1189`, applied `:837`) and `download_stall_timeout_sec` (`:1183`, applied `:1385`), so `agave pull` fails instead of hanging; the API body is still capped at `max_api_response_size` 10 MiB (`:35`, checked `:873`).
- Retargeting: `HF_ENDPOINT` changes the base for every subsequent request and is validated only as an http(s) URL (`src/pull.zig:453`, check `:460`); a hostile env value redirects the download to an operator's own host. Env is a trusted input, so this is listed for completeness, not as an external threat.

**GitHub releases -> local filesystem (`agave update`)**
- Tampering / elevation: whoever controls the release host, the repo contents, or a redirect in the asset chain chooses the bytes that become the installed binary. Controls present: HTTPS only, `trustedGithubUrl` on both the asset and the sidecar (`src/update.zig:502`), SHA-256 match against the sidecar (`checksumMatches` `:159`), exact-tag asset naming (`writeAssetName` `:79`, `sameRelease` `:60`), size caps `:25-27`, a per-read stall bound (`fetch_stall_timeout_sec` `:298`, applied `:344`), and a verdict switch that refuses on every non-`.replaced` outcome. Absent: any signature, a digest pinned outside the release, or a maintainer key: T2.
- Spoofing: `--repo` is operator-supplied and `validRepo` `:97` rejects URLs, extra slashes, and `.`/`..`, so the release host cannot be redirected by a crafted repo argument; the download URL must still pass `trustedGithubUrl`.
- DoS: `fetchBody` size caps keep a hostile response from exhausting memory; a 256 MiB asset download is a local CLI cost, not a service risk.
- Repudiation: `GITHUB_TOKEN` is optional; without it GitHub rate-limits the API call and `update` fails rather than proceeding. The install prints the version it installed, which is the only durable record.

**Peer node <-> peer node**
- All six STRIDE classes apply with no control present: spoofed rank joins, tensor tampering via allReduce (`src/parallel/transport.zig` `allReduceAdd` `:530` / `tcpAllReduce` `:585`), repudiation impossible (no identity), disclosure via disagg KV stream = full prompt transcript (`src/models/qwen35.zig:2277` `sendKvCache`, call site `src/main.zig:4051`), DoS via connection race against `max_peers` (`src/parallel/transport.zig:270,312`), elevation by becoming rank 0 through spoofed beacons (`src/parallel/peer_discovery.zig:28-29`). `tcpRecv` fails on short reads rather than zero-filling; that does not authenticate the peer: T1.

**Local processes -> shm**
- Tampering/disclosure by same-uid processes on predictable names (`src/parallel/transport.zig:333-334`). `shm_unlink` then `O_EXCL` create discards a pre-planted send segment, then fails if a racer recreates it; it does not randomize the name: T6. The send-size guard is a ReleaseFast-stripped `std.debug.assert`.

**Process -> KV spill file (SSD tier)**
- Disclosure: the SSD tier writes per-block K/V arrays straight to the operator-named path (`src/kvcache/tiered.zig:549-550`, opened `0644` at `:245`). That is prompt-derived hidden state readable by any local user, where the conversation store deliberately publishes owner-only (`src/durable_file.zig:152`, `replacePrivate` `:163`). The path itself is filtered (traversal, absolute, NUL refused, `:238-240`), and the file is deleted on teardown (`:344`), so a crash or SIGKILL leaves the spill behind with no cleanup: T11. Gated behind `--kv-tiers vram+ram+ssd`, which needs a unified-memory backend.

**Artifact -> process, implicit path (`.cal`, steering, token map)**
- Tampering without a named file flag: `--kv-eviction tri` derives the calibration path from the model path itself (`calPathForModel` `src/calibrate.zig:539`, call site `src/main.zig:3234`), so a `.cal` file next to a downloaded model is consumed with no trace beyond the flag. `readCalFile` (`:550`) checks magic (`:557`), version (`:563`), `n_bands != 0` (`:572`), and exact array lengths; `ropeFrequencies` refuses a non-finite or non-positive `theta` (`src/ops/kv_evict.zig:358`). All bounds, no provenance: a co-placed file chooses which KV positions survive eviction, so answers shift without any visible switch. T12.
- The steering and token-map files are named explicitly by the operator (`--dir-steering-file` `src/main.zig:3116`, `--spec-token-map` `src/main.zig:4726`), sized exactly (`src/steering.zig:54`) or capped (`src/spec/spec_decode.zig:498`), and a failed load is non-fatal. Lower risk than T12 because the operator chose the path.

**Process -> conversation file**
- Disclosure: the JSON store is plaintext prompts (`src/server/conv_store.zig`). Load refuses files > 64 MiB (`max_store_bytes` `:39`); every write is `durable.replacePrivate`, i.e. owner-only 0600 (`src/server/conv_store.zig:140`, mode `src/durable_file.zig:152`). Compose persists it in `agave-cache` (`docker-compose.yml:65`): T7.
- Tampering by a local reader is out of reach (0600), but an *over-cap* store is quarantined and its tail dropped on the next save (`src/server/conv_store.zig:383,534`), which is a silent-loss path an operator should know about.

## 5. Abuse cases (authenticated-hostile-user scenarios)

1. **Budget denial:** one key holder streams maximal requests. With limits unset, nothing throttles GPU time. With limits set, the single global TPM/RPM bucket starves every other client (`src/server/rate_limiter.zig:58`).
2. **Cross-request state reach:** a key holder exports `/v1/kv_cache` after other users' traffic and receives hidden-state blocks derived from their prompts on a shared single-key deployment (`src/server/server.zig:2957`; the radix prefix cache is likewise global, `src/server/scheduler.zig:314,434,719`).
3. **Replay theft:** a key holder re-sends another holder's `X-Request-Id` to `/v1/chat` and receives their stored completion, up to 64 KiB, for an hour after the original request (`src/server/idempotency.zig:161,56`, replay path `src/server/server.zig:1505`). T9.
4. **Retry suppression:** presenting a key that is still `in_flight` collapses into a duplicate rejection, so a hostile holder can deny a victim's in-progress retry (`src/server/idempotency.zig:58,161`; `.duplicate` branch in `resolveIdempotency` `src/server/server.zig:1474`).
5. **Latency gaming:** repeated user-supplied GBNF grammars or `json_mode` force inline parse-and-constrain outside the batch scheduler, degrading concurrent clients (`src/server/server.zig:4307-4308,4947,5753`; grammar size bounded by `src/grammar.zig:22-25`).
6. **Tokenizer abuse:** `/v1/tokenize` and `/v1/detokenize` accept arbitrary attacker text and run the vocabulary scan under the same single global bucket as generation, so a cheap endpoint can occupy the tokenizer's share of request time (`src/server/server.zig:2768,2854`; caps `src/server/json.zig:19`). T8.
7. **Model fingerprinting:** `/v1/models` names the loaded model, backend, layer/embedding/vocab counts, context size, and MTP depth to any holder of one key, which narrows the set of suitable attacks against that deployment (`src/server/server.zig:2465`).
8. **Cluster hijack (no auth needed):** a LAN host answers the UDP beacon first or wins the TCP connect race and becomes a trusted rank, then feeds arbitrary f32 tensors (`src/parallel/transport.zig:270,312`, `src/parallel/peer_discovery.zig:28-29`).
9. **Prompt harvest from disk:** on a shared Unix user or a leaked compose volume, read `conversations.json` (`src/server/conv_store.zig:107`). With the SSD tier enabled, the same reader can read live KV from the spill file too, which is `0644` rather than the conversation store's owner-only mode (`src/kvcache/tiered.zig:245`; `src/durable_file.zig:152`): T11.
10. **Forced update to a hostile build (no auth needed, needs a run):** an operator (or anything that can set `GITHUB_TOKEN`, `HF_ENDPOINT`, or a proxy's trust store) who runs `agave update` against a repo or a network position they control gets bytes written over the installed binary. The command's own defenses are real but all rooted in the same trust domain as the download: `src/update.zig:127,159,177`. T2.
11. **Client-side trust note:** the `--serve` web UI enforces nothing itself; all checks are server-side (correct posture). The standalone browser demo will load any model URL a visitor types (`web/agave.ts:403`), so a linked model can serve attacker-chosen completions locally, inside the sandbox.
12. **Answer steering through model state (key holder only):** `POST /v1/kv_cache` with a right-sized f32 blob writes chosen hidden state into the live cache (`src/server/server.zig:3047`), then `/v1/kv_cache` GET returns it and the next completion is computed over it (`src/models/gemma4.zig:1664-1668`). No provenance check separates a warm-start blob from an injected one: T10.
13. **Answer steering through co-located files (no HTTP access):** dropping a `.cal` next to the model changes eviction scoring under `--kv-eviction tri` without touching the command line (`src/calibrate.zig:539`, `src/main.zig:3234`): T12.
14. **Silent model-state takeover via a failing LoRA apply:** an adapter that merges several tensors and then fails used to leave the already-merged overrides published with no handle to dispose them, so the run continued on a partially-merged model. The rollback (`src/lora.zig:86,209`) closes it; the abuse case is recorded because it is the class a hostile adapter would aim for, and it is worth a regression test every time the merge path is touched.

## 6. Gaps requiring sec-review follow-up (ranked)

1. T2: sign the release, or pin a digest in-repo, so the sidecar is not the only trust anchor. Until then `agave update` is as strong as TLS to GitHub.
2. T1: add authentication (preshared secret at minimum) and identity handshake to TP/PP/disagg/discovery protocols. Do not treat the HTTP API key as covering those ports.
3. T3: pin downloads to commit SHAs; verify checksums/signatures. Magic-byte + size is not integrity.
4. T9: namespace the idempotency ledger by a derived principal (key hash plus client identity), or refuse a `X-Request-Id` that is already claimed by a different requester.
5. T4: document single-trust-domain status explicitly, or namespace caches/stores per key.
6. T5: per-key rate buckets; route grammar / `json_mode` through the scheduler. The limiter stays off unless flags are set, so operators who bind non-loopback with a key and no rpm/tpm have no compute quota.
7. T10: treat a KV import blob as untrusted model state. It is length-checked and lock-protected, but a key holder can still choose the hidden state every later answer is computed from; gate import behind a distinct capability, or at minimum log it as a state-mutating event distinct from a read.
8. T8: give `/v1/tokenize` and `/v1/detokenize` their own cheap quota, or document them as sharing the generation bucket.
9. T6: randomized shm names (`src/parallel/transport.zig:333-334`); keep a runtime (non-assert) send-size check in ReleaseFast.
10. T11: create the SSD spill file with the owner-only mode the conversation store uses (`src/durable_file.zig:152`) instead of `0644` (`src/kvcache/tiered.zig:245`), and remove a stale spill file at startup, not only on clean teardown.
11. T12: require an explicit `--cal` path (or log the derived path and refuse a file the operator did not name) so a `.cal` next to a model cannot silently change eviction behaviour.
12. T7: treat the conversation file as sensitive data (permissions already follow `replacePrivate`; no at-rest encryption), and decide whether the `{path}.deleted[.N]` sidecar tier should be included by default in what an operator is told is retained.
13. Response path: [SECURITY.md](../SECURITY.md) records that no dedicated disclosure contact or fix-shipped SLA is defined in-repo (organizational; not invented here).
14. Observability: auth failures log `authentication failed` and increment `agave_requests_auth_failed_total` (`src/server/server.zig:1991-1992`, `src/server/metrics.zig:287`). Logs are process stdout (compose `json-file` 10m x 3). There is still no durable audit trail an incident investigation can replay independently of the container log driver. `agave update` additionally writes no audit record beyond one stdout line, so a replaced binary is not distinguishable from a replaced binary later.

## 7. Response readiness (note only)

- Security-relevant events that do exist in logs: request start/done with `req=` / `xid=` (`logRequest` `src/server/server.zig:1219`, `logRequestDone` `:1234`), Host/Origin/`Sec-Fetch-Site` rejects (`:2287,2300`), 401s (`send401` `:1990`), oversized-body 413 (`:7562`) and pre-routing 400, connection-capacity 503 (`:7856`).
- `X-Request-Id` copied into access logs is length-capped at 64 bytes (`max_client_request_id_len` `:100`, cap enforced in `sanitizeClientRequestId` `src/server/http.zig:117`), so a hostile client cannot flood the log with an unbounded correlation string. The same cap bounds the ledger key.
- Hostnames, paths, and ids that reach a log line pass through `sanitizeForLog` (`src/server/server.zig:1182`), which replaces C0/C1 control codepoints and invalid UTF-8 so a header cannot inject a terminal escape.
- `agave update` failures are reported on stderr with the reason and exit non-zero; a successful install prints the new version. There is no log file, signature, or system-level record of the replacement.
- No in-repo path from "vulnerability reported" to "fix shipped" beyond public GitHub issues. See [SECURITY.md](../SECURITY.md).

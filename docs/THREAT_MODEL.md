# Agave Threat Model

Living model of what this codebase exposes to attack, what it costs when attacked, and which controls stand in the way. Findings feed sec-review; this file does not prescribe code fixes.

- **Last reviewed:** 2026-10-08 (every `path:line` below re-resolved by content-matching the referenced line against source in this pass, from the 2026-10-07 baseline; boundary 11 and threat T13 added this pass)
- **Owner / review cadence:** organizational fields, to be assigned; not defined in-repo
- **Scope:** inference CLI (`src/main.zig`), HTTP server (`src/server/`), model loaders (`src/format/`), Hub downloads (`src/pull.zig`), the self-updater (`src/update.zig`), distributed transports (`src/parallel/`), WASM/browser demo (`web/`, `src/wasm_entry.zig`), container artifacts (`Dockerfile`, `docker-compose.yml`)
- **Out of scope:** backend kernel internals beyond their input parsing; GPU driver attack surface

Disclosure and supported-version policy: [SECURITY.md](../SECURITY.md). HTTP contract: [API.md](API.md).

Every reference below is `path:line` plus the symbol or literal at that line, so a later drift is cheap to detect without a full re-read. The 2026-10-08 pass re-resolved all of them mechanically: each referenced line's text was matched against the same file at the previous revision's commit and the new line number written in its place, so a moved symbol follows its code rather than keeping its old address. A reference that no longer matches any line in the file is stale, not approximate — treat it as a finding, not a rounding error. `zig build docs-check` (`scripts/check-docs.py` `check_doc_line_refs`) catches only the gross form of drift, a missing file or a line past EOF, so that re-resolution still has to be redone each pass. Bare `` `:NNN` `` refs are a standing hazard: they bind to the last `file.zig` mentioned earlier in the same line, which is wrong the moment a sentence cites two files. Where that happens the file is now named explicitly at each ref; keep it that way when editing.

|---|--------|----------|--------|--------|
| T1 | Any LAN host can join an inference cluster or inject tensors: TP/PP/disagg/discovery have no authentication | Peer node -> node (TCP 49454/49455/49456; UDP discovery reuses the same numbers) | Wrong outputs accepted as correct; full prompt transcript theft via disagg KV stream | **No mitigation.** No peer credential check anywhere in `src/parallel/` |
| T2 | `agave update` overwrites the running executable with bytes from a third-party host; the SHA-256 sidecar it checks against is fetched from the same host in the same run | GitHub -> local filesystem | Arbitrary code execution as the invoking user, at the next start of the binary | Partial: HTTPS-only, `trustedGithubUrl` host allowlist, SHA-256 sidecar, size caps. | T4 | Single-key deployments have no tenant separation: `/v1/kv_cache` export and the global prompt-prefix / radix cache cross request owners | Client -> client (same server) | One API-key holder reads KV state derived from another user's prompts | Documented limitation, unmitigated |
| T5 | Rate limiting is one global bucket, default off; grammar/json_mode bypass the batch scheduler | Client -> compute | One client exhausts GPU time / latency for all | Partial: caps exist, identity does not |
| T6 | Predictable shared-memory names let any same-uid local process read/inject tensors | Local process -> shm | Local tensor injection during `--tp 2` same-host runs | Mode 0600 + `O_EXCL` after `shm_unlink` only |
| T7 | Conversation store persists prompts to disk (`$XDG_CACHE_HOME/agave/conversations.json`); `action=delete` destroys the live copy | Process -> filesystem | Prompt transcript survives process exit and, for a deleted conversation, survives until the pre-deletion sidecar or the backup tier is also lost | Owner-only mode 0600 (`durable_file.private_file_mode`), pre-deletion snapshot `conv_store.snapshotBeforeDelete`, no encryption; compose volume `agave-cache` holds it |
| T8 | `/v1/tokenize` and `/v1/detokenize` run the tokenizer on attacker-chosen text with no per-endpoint quota | Client -> compute | Tokenizer CPU burn on loopback deployments; detokenize is a decode oracle over vocabulary | Bounded by 1 MiB body and 128-message scan cap; no endpoint-level rate limit |
| T9 | The idempotency replay ledger is global and keyed only on the client-supplied `X-Request-Id` | Client -> client (same server) | One key holder replays another holder's stored `/v1/chat` reply (up to 64 KiB, 1 h retention), or suppresses their retry | The ledger API scopes claims to `Owner`, but the server uses one shared `anonymous_owner` for every authorized caller; no tenant isolation: T4 |
| T10 | `POST /v1/kv_cache` lets any key holder write attacker-chosen f32 hidden state into the live cache; `n_tokens` alone sizes the write | Client -> compute (and client -> client) | Every later answer for that slot is computed over injected K/V. Bounded by `importKvPrefix` size checks (`src/models/gemma4.zig:1654`), not by any integrity control | Partial: length-validated against per-layer KV, taken under the model + scheduler locks (`src/server/server.zig:3061-3067`) |
| T11 | `--kv-tiers vram+ram+ssd` spills live KV hidden state to a world-readable `0644` file at the operator-supplied `--kv-ssd-path` | Process -> filesystem | Any local user reads prompt-derived KV from the SSD tier; the file is deleted on clean shutdown (`src/kvcache/tiered.zig:344`), so a crash leaves it behind | Path traversal / absolute-path / NUL rejected (`src/kvcache/tiered.zig:238-241`); **file mode is `0644`, not the private mode the conversation store uses** |
| T12 | A `.cal` file sitting next to the model is auto-loaded under `--kv-eviction tri` and silently steers eviction scoring; the path is derived, never operator-supplied | Artifact -> process (implicit) | Co-located file changes which KV positions survive, degrading or skewing answers with no command-line trace | Partial: magic + version + length checks (`src/calibrate.zig:550-585`), non-finite `theta` rejected (`src/ops/kv_evict.zig:358`); no signature and no prompt to confirm the file was expected |
| T13 | Text that reaches a prompt from an untrusted source (a document, a web page, another user's turn, a tool result) is read by the model and its output is parsed back into **tool calls** the caller then executes | Untrusted content -> prompt -> model output -> caller's tool executor (CWE-1427 / CWE-74) | Whoever supplies the text picks which declared tool fires and with which arguments, on a server that has no authority boundary between "model said so" and "caller may do so" | Partial: prompt-borne tag stripping (`src/chat_template.zig:445-446`), declared-name allowlist (`src/server/server.zig:1715`, `:1688`), per-response cap of 32 calls (`src/server/server.zig:109`, enforced `:1830`). The reachable set is the request's declared tools plus the process registry, which is empty by default (`src/server/server.zig:645`) and widens the target only if an embedder registers into it. The server cannot tell an injected call from a requested one; only the caller can |

Highest-value correction for operators: **the API key protects only TCP 49453**. The TP/PP/disagg data ports and UDP discovery are separate listeners that never see it. Within 49453 the key authenticates but does not partition: everything a key holder sends shares one KV cache, one radix prefix cache, one conversation store, and one replay ledger.

Second correction, in the other direction: **the API key is the wrong control to look for on prompt-borne tool calls**. Anyone who can put text into a prompt is a content attacker, not a network attacker; no key is required to reach that boundary, and possessing the key does not reduce it. See T13 and section 3, "Untrusted content -> prompt -> tool call".

## Assets

- The installed `agave` binary: `agave update` replaces it in place (`replaceVerified` `src/update.zig:193`, caller `replaceExecutable` `src/update.zig:364`), so compromising the download path is code execution with the operator's privileges. T2.
- Model weights on disk and in VRAM: expensive to obtain, exfiltration target.
- Prompt and conversation content: in memory; in the bounded conversation store (`max_conversations` = 100 `src/server/conv_store.zig:43`, `max_messages_per_conv` = 1000 `:44`, re-exported into the server at `src/server/server.zig:127,128`); on disk via `src/server/conv_store.zig` (`defaultPath` `:107`, `$XDG_CACHE_HOME` `:108` else `$HOME` `:109`); latent in the KV cache and radix prefix cache (`src/server/scheduler.zig` `radix_tree` field `:323`, `matchPrefix` call `:443`, `insert` call `:728`).
- Generated response bodies retained for replay (`src/server/idempotency.zig` `max_body_len` 64 KiB `:56`, `retention_ms` 1 h `:61`, `in_flight_ttl_ms` 5 min `:58`).
- Hidden states: `/v1/kv_cache` export returns raw per-layer KV blocks, capped at 64 MiB (`kv_export_max_bytes` `src/server/server.zig:122`, route `src/server/server.zig:2978`). The same values can be **written in** by import (`src/server/server.zig:3068`) and are spilled to disk when the SSD tier is on (`src/kvcache/tiered.zig:549`): T10, T11.
- Credentials in process env: `HF_TOKEN` (`src/pull.zig:338` `config.getenv("HF_TOKEN")`), `GITHUB_TOKEN` (`src/update.zig:455`), `AGAVE_API_KEY` (`src/main.zig:1379` `preferredSecret`, definition `:1672`).
- GPU compute and availability: generation is the costly resource; DoS converts directly to cost.
- Output integrity: poisoned weights, a poisoned allReduce, or an update-channel substitution silently corrupt every answer.

## 2. Trust boundaries and data flow

1. **Client -> HTTP API.** Authn point: one dispatcher chokepoint, `authorizedForPath` (`src/server/server.zig:1423`, call site `:2358`, table lookup `authPolicyFor` `:439`), which calls `validateAuth` (`:1396`, constant-time compare helper `constantTimeEql` `:1434`) for every route whose `known_endpoints` entry is `AuthPolicy.required`. The default for a new or unlisted path is `required` (`src/server/server.zig:413,439`), so a route cannot become reachable without the key by omitting a check; only `/health` and `/ready` (`.optional`) and `/favicon.ico` (`.public`) opt out, and the first two still trim their body when `validateAuth` fails (`:2384`, `:2405`). Deny side pinned by `test "auth chokepoint denies every protected route"` (`:9663`, unknown-path and case-variant asserts `:9697-9698`). Policy: non-loopback binds refuse to start without a key (`src/main.zig:1384`), and an empty key is rejected rather than accepted as "present" (`src/main.zig:1392`); loopback binds are open by design. Unauthenticated mode additionally rejects non-loopback `Host` (DNS rebind, `isRebindHostUnauthenticated` `src/server/server.zig:1119`, applied `:2308`, backed by `isLoopbackHttpHost` `src/server/http.zig:178`), mismatched `Origin` vs `Host`, and `Sec-Fetch-Site: cross-site` (CSRF / drive-by browser, `isCrossOriginUnauthenticated` `src/server/server.zig:1133`, applied `:2321`, over `isCrossSiteFetch` `src/server/http.zig:149` and `originMatchesHost` `src/server/http.zig:128`). A client that sends none of those headers (curl, SDKs, probes) is unaffected.
2. **Client -> client (same server).** No principal is derived from the key. The KV cache, radix prefix cache, conversation store, and idempotency ledger are all per-server singletons shared by every request: T4, T9.
3. **Artifact -> loader.** Whoever supplies the file (local user, Hub download, LoRA adapter, mmproj, PNG/PPM) crosses into mmap/decode native code. Validation lives inside the parsers (see mitigations).
4. **HF Hub -> local cache.** Transport-authenticated (TLS) but content-unverified; blobs land under `$HF_HOME`-derived paths with `O_NOFOLLOW` writes (`src/pull.zig:1335`). Commit SHA is used for snapshot directory naming, not as a pin on the download URL (`resolve/main` `src/pull.zig:1140`).
5. **GitHub releases -> local filesystem.** `agave update` is the only code path that overwrites a file the user executes. The channel is HTTPS with a GitHub host allowlist (`trustedGithubUrl` `src/update.zig:127`, userinfo and `github.com.evil.com` refused, tests `:584-586`), and the payload must match a `.sha256` sidecar (`checksumMatches` `:159`, sidecar name `writeSidecarName` `:83`). Both the asset and the sidecar come from the same release in the same run, so the digest proves transfer integrity, not publisher identity: T2. No code signature, no pinned digest, and the sidecar is not itself signed.
6. **Peer node -> this node (TP/PP/disagg).** No authentication point exists anywhere on this boundary. Any host that connects is accepted into a rank slot subject only to the `max_peers` cap (`src/parallel/transport.zig` `acceptPeer` `:312`, connect-side check `:270`); first UDP `AGAVE-JOIN` responder wins discovery (`src/parallel/peer_discovery.zig:65`). Largest unauthenticated boundary.
7. **Same-host processes -> shm segments.** Only uid/file-mode checks; names are fixed.
8. **Secrets -> process.** Env vars enter once at startup; nonempty `AGAVE_API_KEY` wins over CLI to avoid `ps` exposure (`src/main.zig:1220-1224`, `preferredSecret` `:1672`); empty env is unset. `GITHUB_TOKEN` is read by `agave update` and is sent as a bearer to `api.github.com` only (`src/update.zig:455`). Rotation: process restart. Storage: env only. Prompt-derived buffers are wiped before free (`wipeFree` / `wipeFreeTokens` `src/server/server.zig:1171,1177`), the per-connection read buffer that carries `Authorization` / `x-api-key` is zeroed before it is freed (`:7621`, freed `:7623`), and Hub `Authorization` buffers are zeroed (`src/pull.zig:809,1234`).
9. **Process -> conversation file.** Prompts written to the cache-path conversation store unless `--no-conv-store` (`src/server/conv_store.zig` `defaultPath` `:107`, `save` `:130` via `durable.replacePrivate` `:140`). Compose maps this under `agave-cache` (`docker-compose.yml:65`). A destructive API call (`action=delete` `src/server/server.zig:3495`, plus the UI `/clear` and `/reset` commands) snapshots the store aside first (`snapshotBeforeDeletion` `src/server/server.zig:3982` -> `conv_store.snapshotBeforeDelete` `src/server/conv_store.zig:275`, `{path}.deleted[.N]` at owner-only mode, `max_sidecar_copies` 8 `:552`); the snapshot is best-effort and its failure is logged, not fatal, so a full sidecar tier degrades to the backup tier alone.
10. **Embedded UI -> jsDelivr.** `src/web/chat/markdown.ts` fetches marked / DOMPurify / highlight.js from `cdn.jsdelivr.net` (URLs `:13,15,17`, pinned SRI hashes `:14,16,18`) with the hashes checked in `loadCdnScript` (`:54`, `script.integrity` `:57`) on the first response and the first code block rather than on page load. A stalled CDN resolves false after the timeout so the plain-text fallback settles. CSP allowlists that origin for scripts only (`src/server/http.zig:384`); no stylesheet is fetched, so `style-src` stays `'unsafe-inline'` alone. Compromise of the CDN without a matching hash is blocked; a rebuild that changes both script and hash is a build-time event.

11. **Untrusted content -> prompt -> model output -> caller's tool executor.** The one boundary whose attacker is not a network peer. Text the server never authored (a retrieved document, a pasted page, a prior turn, a tool result fed back in) is formatted into a prompt and read by the model; whatever the model emits between `<tool_call>` tags is parsed into a structured call and returned to the caller. The format step is the only place a control can be applied before the model sees the text, and the parse step the only place one can be applied after: stripping is `collectControlTokens` (`src/chat_template.zig:438`, tags added first at `:445-446` so a full table cannot displace them), parsing is `nextAllowedToolCall` (`src/server/server.zig:1715`) with the declared-name allowlist inline at `:1725-1729` and the per-response cap at `:1830`. T13.

Privilege transitions: one at runtime, and one the process does not mediate. The process starts and stays at its launching privilege; the Dockerfile drops to `agave` before exec (`Dockerfile:246`), and compose adds `no-new-privileges` (`docker-compose.yml:75`). `agave update` is the one deliberate write to an executable the user runs (`src/update.zig:364`), gated on the verdict of `decide` (`:177`) and confined to the release asset's bytes.

The transition the process does *not* mediate is a logical one, and it is the only boundary with no listener behind it. A `<tool_call>` block in model output becomes a structured tool call in the response, and the **caller's** executor runs it. The server validates the shape (name declared, arguments a complete JSON object) but performs no authorization: it has no store, no user, and no session to check a call against. The effective authority is therefore the caller's, exercised on the caller's behalf by text the model produced from whatever happened to be in the prompt. That is the boundary recorded as T13, and it is why the API key is not a control for it: an attacker supplying the *content* needs no key at all, while a legitimate key holder is not the threat actor.

## 3. Threats per boundary

**Client -> HTTP API**
- Spoofing: key guessing. Mitigated: constant-time compare, non-empty key enforcement (`src/server/server.zig:1396,1434`, `src/main.zig:1384,1392`).
- Information disclosure: `/health` and `/ready` reachable unauthenticated (reduced bodies; `docs/API.md` health/ready sections match code at `src/server/server.zig:2374-2441`). Residual: build info on `/metrics` requires auth (`:2445`); `/v1/models` (`:2486`) discloses model geometry to any key holder.
- Tampering/DoS: oversized or hostile JSON. Mitigated: 1 MiB body cap (`http_buf_size` `src/server/server.zig:98` / `max_request_body_size` `src/server/server.zig:120`, enforced `src/server/server.zig:7624`), duplicate `Content-Length` rejection (`parseContentLength` `src/server/http.zig:306`), `Transfer-Encoding` rejected to avoid request smuggling (`src/server/http.zig:357`), scan-based JSON with message/tool caps (`src/server/json.zig:19,39`), connection cap 64 (`max_concurrent_connections` `src/server/server.zig:133`, enforced `src/server/server.zig:7920` with a 503 + `Retry-After` via `send503Retry` `src/server/server.zig:2061`), 30 s read timeout (`connection_read_timeout_sec` `src/server/server.zig:459`, applied `src/server/server.zig:7591`).
- CSRF / DNS rebind on no-key loopback: mitigated by `Sec-Fetch-Site` + Origin vs Host (`src/server/server.zig:1133`, `src/server/http.zig:149,128`) and loopback-only Host (`src/server/server.zig:1119`). Residual: any local process can still call the no-key loopback API (curl, scripts).
- DoS: budget exhaustion. Partially mitigated: rate limiter exists but is one global bucket (`src/server/rate_limiter.zig:58`, `TokenBucket` `:23`, `RateLimiter` `:61`, `tryConsumeOrRetryAfter` `:126`). CLI default is 0 = limiter disabled (`src/main.zig:679,681`, wired `:3967`; unset side falls back to `rate_limit_unlimited_rpm` / `_tpm` `src/server/server.zig:142-143`, install site `:7792-7795`). Grammar and `json_mode` bypass the batch scheduler and run inline instead (`use_grammar_pre` at `src/server/server.zig:4328`, scheduler guard `:4329`; the same shape repeats per route at `:4979` and `:5809`).
- Repudiation: request identity is a client-supplied `X-Request-Id`, length-capped (`max_client_request_id_len` `src/server/server.zig:104`, sanitize `sanitizeClientRequestId` `src/server/http.zig:117`, capture `captureClientRequestId` `src/server/server.zig:1110`), so a log line cannot be tied to a client beyond a self-declared id.
- Elevation: none known; single-process, no privileged helpers, no request-scoped tool execution.


**Untrusted content -> prompt -> tool call**
- Tampering / elevation (CWE-1427, CWE-74): the attacker supplies *content*, not a request. A document, a page, a ticket, or an earlier turn of someone else's conversation is formatted into a prompt; the model reads it as instructions; the tags it emits are parsed into tool calls the caller executes. The server has no way to distinguish an injected call from a requested one, because the request genuinely declared that tool. Mitigated at three points, none of which changes the outcome on a model that complies: the tags are stripped from prompt text before the model sees it (`collectControlTokens` `src/chat_template.zig:438`, added first at `:445-446` so a template with enough EOG and role tokens to fill the fixed table cannot displace them, pinned by `test "tool-call tags are stripped even when the control-token table is full"` `src/chat_template.zig:878`); only a declared name survives the parse (`toolCallNameAllowed` check in `nextAllowedToolCall` `src/server/server.zig:1725-1729`); and one turn returns at most 32 calls (`max_tool_calls_per_response` `src/server/server.zig:109`, enforced `:1830`, repeated per response shape at `:1878`, `:5564`, `:6756`).
- Residual, and it is the real limit of those three: a caller that declares a destructive tool has told the model it may call it. Injected text chooses *which* declared tool fires and with *which* arguments, so the blast radius equals the union of the declared tools. The mitigation that actually bounds it is on the caller's side (per-tool authorization, argument validation, human confirmation), not in this tree. Recorded rather than fixed here.
- Integrity: the model is a confused deputy, not a confused process. The name allowlist is `tp.hasTool(name) or registry.hasName(name)` (`src/server/server.zig:1688`), so the reachable set is the request's declared tools *plus* the process registry. That second half is not gated on the caller naming it, but the registry is empty by default (`tool_registry: tools_mod.Registry = .{}` `src/server/server.zig:645`; `register` is called only from a test, `:8669`), so today the reachable set is exactly the declared set and only an embedder that registers tools widens it. Arguments are the attacker's regardless: `escapedToolCall` (`src/server/server.zig:1758`) escapes name and arguments into the response body, so model output cannot break out of the JSON it is placed in, and `resolveOpenAiToolArguments` `:5663` / `resolveAnthropicToolInput` `:5738` require a single complete object, so a truncated argument is not a valid call.
- DoS: a model that keeps emitting tool tags is bounded at 32 calls per response; the remainder is dropped and logged (`src/server/server.zig:1831`).
- Repudiation: a dropped tool call is logged server-side (`src/server/server.zig:1727`, `:1831`) but the client is not told how many were dropped beyond the array it receives, so a caller cannot distinguish "the model called it and the server suppressed it" from "the model did not call it". Both the cap and an undeclared name are logged; neither is reported in the response.

**Client -> client (shared server state)**
- Information disclosure: `/v1/kv_cache` export (`:2957`) returns blocks derived from other holders' prompts; the radix prefix cache matches across requests (`src/server/scheduler.zig:443`, insert `:728`).
- Information disclosure via replay: the ledger stores the response body for 1 h under the caller's `X-Request-Id` (`src/server/idempotency.zig:56,61`, claim `:161`) and answers a matching key with those bytes (`src/server/server.zig:1514`, dispatch `:1483`). A second key holder who learns or guesses that id receives the first holder's completion without supplying the prompt: T9. The ring is 64 keys (`capacity` `:52`), so guessing is not even necessary for a client that can observe its own ids in the same deployment.
- Tampering/DoS: presenting a key that is `in_flight` yields a duplicate rejection (`src/server/server.zig:1484`), so a hostile holder can deny another holder's retry (in-flight TTL 5 min `src/server/idempotency.zig:58`).
- Tampering of model state: `POST /v1/kv_cache` (`:2957`) reads `n_tokens` from the query (`:2961`, `parsePositiveQueryParam`) and hands the body to `importKvPrefix` (`:3047`) under the server mutex plus the model and scheduler locks (`:3040-3046`). The blob is length-checked per layer against the KV arrays before any copy (`src/models/gemma4.zig:1654-1668`), so a wrong-sized blob is a 400 rather than memory unsafety. Nothing else validates it: the f32 values are attacker-chosen, `kv_seq_len` becomes `n_tokens` (`:1669`), the device KV mirror is invalidated (`:1673`), `kv_valid = true` (`src/server/server.zig:3070`), and every later answer on that slot is computed over the injected hidden state. T10.
- Repudiation of destruction: `action=delete` (`:3474`) has no ledger claim, so a retried or replayed delete is not deduplicated. The pre-deletion snapshot (`src/server/conv_store.zig:275`) is the only in-process record of what the conversation contained.

**Artifact -> loader (GGUF/SafeTensors/LoRA/PNG/PPM)**
- Tampering/DoS: crafted headers driving huge allocations or OOB. Mitigated: GGUF metadata/tensor/array/alignment caps (`src/format/gguf.zig:20-28`), saturating size math (`tensorBytes` `:162`), tensor offsets validated against file size in `parseHeader` `:860`; SafeTensors header capped at 100 MB and checked against file size (`src/format/safetensors.zig:20,264`); shard-name traversal blocked (`isSafeShardName` `:2217`); PNG dimension/inflate caps (`src/image.zig:21,24,27`, enforced `:133,176`).
- Tampering on a failing LoRA apply: an adapter that fails partway used to leave published overrides in the map. Mitigated now: the apply publishes then records, and an append failure restores the previous override or removes the fresh entry (`src/lora.zig:86`, rollback `:209`), pinned by `test "a failed apply rolls every override back"`.
- Residual: unknown GGUF type codes fall back conservatively (`src/format/gguf.zig` default branch on the type switch; non-string arrays are skipped). Fuzz coverage exists: GGUF (`src/format/gguf.zig:1761,1867`), SafeTensors (`src/format/safetensors.zig:4328`), PNG/PPM (`src/image.zig:729`).

**HF Hub -> loader (supply chain)**
- Tampering: repo contents change between listing and blob GET; branch `main` is fetched, not the listed SHA (`src/pull.zig:1140`). Verification ends at GGUF magic bytes + Content-Length match (`verifyGgufBlob` `src/pull.zig:1570`): T3.
- DoS: a hostile or compromised endpoint that accepts the connection and then stalls is bounded by `api_stall_timeout_sec` (60 s, `src/pull.zig:1189`, applied `:837`) and `download_stall_timeout_sec` (`:1183`, applied `:1385`), so `agave pull` fails instead of hanging; the API body is still capped at `max_api_response_size` 10 MiB (`:35`, checked `:873`).
- Retargeting: `HF_ENDPOINT` changes the base for every subsequent request and is validated only as an http(s) URL (`src/pull.zig:453`, check `:460`); a hostile env value redirects the download to an operator's own host. Env is a trusted input, so this is listed for completeness, not as an external threat.

**GitHub releases -> local filesystem (`agave update`)**
- Tampering / elevation: whoever controls the release host, the repo contents, or a redirect in the asset chain chooses the bytes that become the installed binary. Controls present: HTTPS only, `trustedGithubUrl` on both the asset and the sidecar (`src/update.zig:502`), SHA-256 match against the sidecar (`checksumMatches` `:159`), exact-tag asset naming (`writeAssetName` `:79`, `sameRelease` `:60`), size caps `:25-27`, a per-read stall bound (`fetch_stall_timeout_sec` `:298`, applied `:344`), and a verdict switch that refuses on every non-`.replaced` outcome. Absent: any signature, a digest pinned outside the release, or a maintainer key: T2.
- Spoofing: `--repo` is operator-supplied and `validRepo` `src/update.zig:97` rejects URLs, extra slashes, and `.`/`..`, so the release host cannot be redirected by a crafted repo argument; the download URL must still pass `trustedGithubUrl`.
- DoS: `fetchBody` size caps keep a hostile response from exhausting memory; a 256 MiB asset download is a local CLI cost, not a service risk.
- Repudiation: `GITHUB_TOKEN` is optional; without it GitHub rate-limits the API call and `update` fails rather than proceeding. The install prints the version it installed, which is the only durable record.

**Peer node <-> peer node**
- All six STRIDE classes apply with no control present: spoofed rank joins, tensor tampering via allReduce (`src/parallel/transport.zig` `allReduceAdd` `:530` / `tcpAllReduce` `:585`), repudiation impossible (no identity), disclosure via disagg KV stream = full prompt transcript (`src/models/qwen35.zig:2277` `sendKvCache`, call site `src/main.zig:4049`), DoS via connection race against `max_peers` (`src/parallel/transport.zig:270,312`), elevation by becoming rank 0 through spoofed beacons (`src/parallel/peer_discovery.zig:28-29`). `tcpRecv` fails on short reads rather than zero-filling; that does not authenticate the peer: T1.

**Local processes -> shm**
- Tampering/disclosure by same-uid processes on predictable names (`src/parallel/transport.zig:333-334`). `shm_unlink` then `O_EXCL` create discards a pre-planted send segment, then fails if a racer recreates it; it does not randomize the name: T6. The send-size guard is a ReleaseFast-stripped `std.debug.assert`.

**Process -> KV spill file (SSD tier)**
- Disclosure: the SSD tier writes per-block K/V arrays straight to the operator-named path (`src/kvcache/tiered.zig:549-550`, opened `0644` at `:245`). That is prompt-derived hidden state readable by any local user, where the conversation store deliberately publishes owner-only (`src/durable_file.zig:152`, `replacePrivate` `:163`). The path itself is filtered (traversal, absolute, NUL refused, `src/kvcache/tiered.zig:238-240`), and the file is deleted on teardown (`src/kvcache/tiered.zig:344`), so a crash or SIGKILL leaves the spill behind with no cleanup: T11. Gated behind `--kv-tiers vram+ram+ssd`, which needs a unified-memory backend.

**Artifact -> process, implicit path (`.cal`, steering, token map)**
- Tampering without a named file flag: `--kv-eviction tri` derives the calibration path from the model path itself (`calPathForModel` `src/calibrate.zig:539`, call site `src/main.zig:3232`), so a `.cal` file next to a downloaded model is consumed with no trace beyond the flag. `readCalFile` (`:548`) checks magic (`:555`), version (`:561`), `n_bands != 0` (`:570`), and exact array lengths; `ropeFrequencies` refuses a non-finite or non-positive `theta` (`src/ops/kv_evict.zig:358`). All bounds, no provenance: a co-placed file chooses which KV positions survive eviction, so answers shift without any visible switch. T12.
- The steering and token-map files are named explicitly by the operator (`--dir-steering-file` `src/main.zig:3114`, `--spec-token-map` `src/main.zig:4724`), sized exactly (`src/steering.zig:54`) or capped (`src/spec/spec_decode.zig:498`), and a failed load is non-fatal. Lower risk than T12 because the operator chose the path.

**Process -> conversation file**
- Disclosure: the JSON store is plaintext prompts (`src/server/conv_store.zig`). Load refuses files > 64 MiB (`max_store_bytes` `:39`); every write is `durable.replacePrivate`, i.e. owner-only 0600 (`src/server/conv_store.zig:140`, mode `src/durable_file.zig:152`). Compose persists it in `agave-cache` (`docker-compose.yml:65`): T7.
- Tampering by a local reader is out of reach (0600), but an *over-cap* store is quarantined and its tail dropped on the next save (`src/server/conv_store.zig:383,534`), which is a silent-loss path an operator should know about.

Single points of failure: the API key alone carries all client-side authn on 49453 and, because no principal is derived from it, also all of the shared-state isolation that does not exist; the loopback-bind default plus the `Sec-Fetch-Site`/Origin checks carry all safety for no-key users; none of it extends to the distributed ports. On the update path, the single SHA-256 sidecar carries the entire publisher-authenticity guarantee, because the digest and the payload share a source. The KV cache is a second one: one endpoint pair both reads it (`GET /v1/kv_cache`) and writes it (`POST`, T10) under the same key, so the single API key guards both directions of the only attacker-reachable model state in the tree.

A third, and the one that is not a control at all: the *caller's* tool executor is the enforcement point for T13, and it sits outside this tree. Every control on the injected-call path -- tag stripping, the declared-name allowlist, the 32-call cap -- sits on the server side of a boundary the server has no authority to close. A reader who assumes the API key or the server's parsing covers this will be wrong: the guarantee ends at the response body, and everything past it belongs to the caller.

- The replay ledger has exactly three call sites, all narrow: `/v1/conversations` action=new (`:3411`), `/v1/chat/regenerate` (`:3525`), `/v1/chat` (`:3759`). `/v1/chat` and `/v1/chat/regenerate` store the response body (`completeIdempotencyKey` `:793`, capped by `max_body_len` 64 KiB `src/server/idempotency.zig:56`, retained `retention_ms` 1 h `:61`); `/v1/conversations` records only a status and content type. Recorded as T9. `action=delete` is *not* one of the three: it is naturally idempotent (deleting a deleted id 404s) but leaves no replay record.
- The conversation store's per-file mode is owner-only, and the SSD KV spill is not. That difference is the whole of T11 and it is one line: `src/kvcache/tiered.zig:245` against `src/durable_file.zig:152`.

## 5. Abuse cases (authenticated-hostile-user scenarios)

1. **Budget denial:** one key holder streams maximal requests. With limits unset, nothing throttles GPU time. With limits set, the single global TPM/RPM bucket starves every other client (`src/server/rate_limiter.zig:58`).
2. **Cross-request state reach:** a key holder exports `/v1/kv_cache` after other users' traffic and receives hidden-state blocks derived from their prompts on a shared single-key deployment (`src/server/server.zig:2978`; the radix prefix cache is likewise global, `src/server/scheduler.zig:323,443,728`).
3. **Replay theft:** a key holder re-sends another holder's `X-Request-Id` to `/v1/chat` and receives their stored completion, up to 64 KiB, for an hour after the original request (`src/server/idempotency.zig:161,56`, replay path `src/server/server.zig:1514`). T9.
4. **Retry suppression:** presenting a key that is still `in_flight` collapses into a duplicate rejection, so a hostile holder can deny a victim's in-progress retry (`src/server/idempotency.zig:58,161`; `.duplicate` branch in `resolveIdempotency` `src/server/server.zig:1483`).
5. **Latency gaming:** repeated user-supplied GBNF grammars or `json_mode` force inline parse-and-constrain outside the batch scheduler, degrading concurrent clients (`src/server/server.zig:4328-4329,4979,5809`; grammar size bounded by `src/grammar.zig:22-25`).
6. **Tokenizer abuse:** `/v1/tokenize` and `/v1/detokenize` accept arbitrary attacker text and run the vocabulary scan under the same single global bucket as generation, so a cheap endpoint can occupy the tokenizer's share of request time (`src/server/server.zig:2789,2875`; caps `src/server/json.zig:19`). T8.
7. **Model fingerprinting:** `/v1/models` names the loaded model, backend, layer/embedding/vocab counts, context size, and MTP depth to any holder of one key, which narrows the set of suitable attacks against that deployment (`src/server/server.zig:2486`).
8. **Cluster hijack (no auth needed):** a LAN host answers the UDP beacon first or wins the TCP connect race and becomes a trusted rank, then feeds arbitrary f32 tensors (`src/parallel/transport.zig:270,312`, `src/parallel/peer_discovery.zig:28-29`).
9. **Prompt harvest from disk:** on a shared Unix user or a leaked compose volume, read `conversations.json` (`src/server/conv_store.zig:107`). With the SSD tier enabled, the same reader can read live KV from the spill file too, which is `0644` rather than the conversation store's owner-only mode (`src/kvcache/tiered.zig:245`; `src/durable_file.zig:152`): T11.
10. **Forced update to a hostile build (no auth needed, needs a run):** an operator (or anything that can set `GITHUB_TOKEN`, `HF_ENDPOINT`, or a proxy's trust store) who runs `agave update` against a repo or a network position they control gets bytes written over the installed binary. The command's own defenses are real but all rooted in the same trust domain as the download: `src/update.zig:127,159,177`. T2.
11. **Client-side trust note:** the `--serve` web UI enforces nothing itself; all checks are server-side (correct posture). The standalone browser demo will load any model URL a visitor types (`web/agave.ts:403`), so a linked model can serve attacker-chosen completions locally, inside the sandbox.
12. **Answer steering through model state (key holder only):** `POST /v1/kv_cache` with a right-sized f32 blob writes chosen hidden state into the live cache (`src/server/server.zig:3068`), then `/v1/kv_cache` GET returns it and the next completion is computed over it (`src/models/gemma4.zig:1664-1668`). No provenance check separates a warm-start blob from an injected one: T10.
13. **Answer steering through co-located files (no HTTP access):** dropping a `.cal` next to the model changes eviction scoring under `--kv-eviction tri` without touching the command line (`src/calibrate.zig:539`, `src/main.zig:3232`): T12.
14. **Silent model-state takeover via a failing LoRA apply:** an adapter that merges several tensors and then fails used to leave the already-merged overrides published with no handle to dispose them, so the run continued on a partially-merged model. The rollback (`src/lora.zig:86,209`) closes it; the abuse case is recorded because it is the class a hostile adapter would aim for, and it is worth a regression test every time the merge path is touched.
15. **Injected tool call (the only abuse case with no key and no network access):** the attacker controls *content* the operator will prompt with -- a document in a retrieval step, a shared conversation, a page an operator pastes in. The text instructs the model to emit `<tool_call>{...}</tool_call>`, and the server hands the parsed call to the caller's executor (`nextAllowedToolCall` `src/server/server.zig:1715`). Tags cannot be smuggled through the prompt text itself (`src/chat_template.zig:445-446`), so the call has to come from the model following the instruction; the blast radius is the set of tools the request declared, not the whole process (`src/server/server.zig:1725-1729`), and one turn is capped at 32 calls (`src/server/server.zig:1830`). What is left is the case worth writing down: for a caller that declares a shell or file-write tool and feeds untrusted text into the same prompt, the attacker has a working trigger, and no setting in this repository turns it off.

## 6. Gaps requiring sec-review follow-up (ranked)

1. T2: sign the release, or pin a digest in-repo, so the sidecar is not the only trust anchor. Until then `agave update` is as strong as TLS to GitHub.
2. T1: add authentication (preshared secret at minimum) and identity handshake to TP/PP/disagg/discovery protocols. Do not treat the HTTP API key as covering those ports.
3. T3: pin downloads to commit SHAs; verify checksums/signatures. Magic-byte + size is not integrity.
4. T9: namespace the idempotency ledger by a derived principal (key hash plus client identity), or refuse a `X-Request-Id` that is already claimed by a different requester.
5. T4: document single-trust-domain status explicitly, or namespace caches/stores per key.
6. T13: the injected-tool-call blast radius equals the union of the tools the *request* declared, and this tree cannot reduce it further. The gap is on the caller's side: per-tool authorization, argument validation against the tool's own schema, and human confirmation for irreversible tools. A caller that declares a broad tool set and feeds untrusted text into the prompt has handed that text a trigger. The server's three controls (tag stripping `src/chat_template.zig:445-446`, declared-name allowlist `src/server/server.zig:1725-1729`, 32-call cap `:1830`) bound *how* the call arrives, not *whether* the injected instruction is followed.
7. T5: per-key rate buckets; route grammar / `json_mode` through the scheduler. The limiter stays off unless flags are set, so operators who bind non-loopback with a key and no rpm/tpm have no compute quota.
8. T10: treat a KV import blob as untrusted model state. It is length-checked and lock-protected, but a key holder can still choose the hidden state every later answer is computed from; gate import behind a distinct capability, or at minimum log it as a state-mutating event distinct from a read.
9. T8: give `/v1/tokenize` and `/v1/detokenize` their own cheap quota, or document them as sharing the generation bucket.
10. T6: randomized shm names (`src/parallel/transport.zig:333-334`); keep a runtime (non-assert) send-size check in ReleaseFast.
11. T11: create the SSD spill file with the owner-only mode the conversation store uses (`src/durable_file.zig:152`) instead of `0644` (`src/kvcache/tiered.zig:245`), and remove a stale spill file at startup, not only on clean teardown.
12. T12: require an explicit `--cal` path (or log the derived path and refuse a file the operator did not name) so a `.cal` next to a model cannot silently change eviction behaviour.
13. T7: treat the conversation file as sensitive data (permissions already follow `replacePrivate`; no at-rest encryption), and decide whether the `{path}.deleted[.N]` sidecar tier should be included by default in what an operator is told is retained.
14. Response path: [SECURITY.md](../SECURITY.md) records that no dedicated disclosure contact or fix-shipped SLA is defined in-repo (organizational; not invented here).
15. Observability: auth failures log `authentication failed` and increment `agave_requests_auth_failed_total` (`src/server/server.zig:2012-2013`, `src/server/metrics.zig:287`). Logs are process stdout (compose `json-file` 10m x 3). There is still no durable audit trail an incident investigation can replay independently of the container log driver. `agave update` additionally writes no audit record beyond one stdout line, so a replaced binary is not distinguishable from a replaced binary later.

## 7. Response readiness (note only)

- Security-relevant events that do exist in logs: request start/done with `req=` / `xid=` (`logRequest` `src/server/server.zig:1228`, `logRequestDone` `:1243`), Host/Origin/`Sec-Fetch-Site` rejects (`:2308,2321`), 401s (`send401` `:2011`), oversized-body 413 (`:7626`) and pre-routing 400, connection-capacity 503 (`:7920`).
- `X-Request-Id` copied into access logs is length-capped at 64 bytes (`max_client_request_id_len` `src/server/server.zig:104`, cap enforced in `sanitizeClientRequestId` `src/server/http.zig:117`), so a hostile client cannot flood the log with an unbounded correlation string. The same cap bounds the ledger key.
- Hostnames, paths, and ids that reach a log line pass through `sanitizeForLog` (`src/server/server.zig:1191`), which replaces C0/C1 control codepoints and invalid UTF-8 so a header cannot inject a terminal escape.
- `agave update` failures are reported on stderr with the reason and exit non-zero; a successful install prints the new version. There is no log file, signature, or system-level record of the replacement.
- No in-repo path from "vulnerability reported" to "fix shipped" beyond public GitHub issues. See [SECURITY.md](../SECURITY.md).
